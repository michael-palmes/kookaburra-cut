## ffmpeg / ffprobe sidecar

The bundled `ffmpeg`/`ffprobe` binaries are a **GPL build** (`--enable-gpl
--enable-libx264 --enable-libx265`). The compiled binaries are **never
committed to this repository**. Every release ships the pair that
[`scripts/build-ffmpeg-sidecar.sh`](scripts/build-ffmpeg-sidecar.sh) builds
in CI (`.github/workflows/release.yml`) from unmodified upstream source,
pinned in that script: ffmpeg 8.1
(`ffmpeg.org/releases/ffmpeg-8.1.tar.xz`, SHA-256 checked), x264 commit
`b35605ace3ddf7c1a5d67a2eb553f034aef41d55` from
`code.videolan.org/videolan/x264` and x265 4.3 (the release tarball, SHA-256
checked). From 0.23.0 every GitHub release attaches the **exact source
archives** the build checked and built from, as its own assets:
`ffmpeg-<version>.tar.xz` and `x265_<version>.tar.gz` byte for byte as their
projects publish them, and `x264-<commit>.tar`, `git archive` of the pinned
commit (its SHA-256 pinned in the script too). Each is listed in the
release's `SHA256SUMS`, covered by its GitHub build provenance attestation and
named with its hash in its SBOM. Together with that script at the release's
tag, which holds every configure flag, they are the **corresponding source**
GPLv2 §3 asks for: anyone can rebuild the sidecar. The script builds x264 from
a clone of the same commit, since x264 takes its version string from git
history. The same build copies the GPL texts out of those sources into the
app (`licenses/sidecar/`). A local `pnpm setup:ffmpeg:release` runs the same
script.
